# Sessions

## Overview

Chat sessions: create, list, search, update, delete, per-agent.
Backend: backend/app/api/v1/sessions/router.py.

## API surface

- GET / (list), GET /search, GET /{session_id}
- POST / (create), PUT /{session_id}, DELETE /{session_id}
- POST /bulk-delete, DELETE / (all), DELETE /all
- GET /agent/{agent_id}

## Session metadata fields (from ChatSession model)

| Field | Type | Notes |
|-------|------|-------|
| `id` | int | PK |
| `title` | str(200)? | auto-generated by the TitleService (or manual rename) |
| `agent_id` | int | FK → agents.id (cascade delete, indexed) — sessions are per-agent |
| `is_active` | bool | default true, indexed |
| `source` | str(20) | default "agent" — source tracking (Phase D conversation logging) |
| `created_at` / `updated_at` | datetime | server_default now(); updated_at onupdate now() |

Messages live in `chat_messages` (FK session_id, cascade delete).

## Summarization — does NOT exist

There is **no conversation-summarization feature** in the current
codebase. The old conversation-summarization-guide refers to a
feature that was never built (or was removed). The only
"summarize" in the code is the **SummarizeLlmTool** — a builtin
agent tool for summarizing *content*, unrelated to session
summarization. This page deliberately does not document session
summarization until the feature exists (2026-08-07 verification).

## Key facts

- Sessions store chat history (chat_sessions + chat_messages);
  session IDs are the unit of conversation continuity.
- The chat router's generate_stream persists messages into the
  current session; sessions are the UI's conversation list source.
- Per-agent session listing: GET /agent/{agent_id}.
