# The Title Capability

Session titles are generated by the **title capability** — a thin
service over the provider registry. It is NOT a separate LLM
config; it resolves through the same provider rows and alias map
the chat executors use.

## Resolution chain

The capability resolves its LLM in this order:

1. **Per-request model override** — the frontend's title-model
   preference: the active agent's model (`agent`), a user-typed
   model string (`custom`), or nothing (`backend_default`).
2. **The DB default provider row** — used when no override is
   sent (`backend_default`). This is the same row the workflow
   layer falls back to.
3. **No silent fallback** — a failed resolution leaves the service
   unresolved and logs `TITLE-GEN CONFIG FAILED`; the caller
   surfaces the error. There is no second-best provider behind the
   scenes.

## The reasoning rule

Reasoning models "think" before answering. On a 3–5-word title
that thinking consumes the entire token budget and the model
returns an EMPTY title. The capability therefore applies
`reasoning_effort="none"` for reasoning-capable cloud rows
(deepseek and similar). Local servers (the llama-server's openai
adapter) REJECT the kwarg and never receive it — the rule is
provider-aware, never universal.

## Failure logging

Two structured, grep-able markers:

- `TITLE-GEN CONFIG FAILED` — resolution failed (no row / invalid
  row / missing key). No fallback is attempted.
- `TITLE-GEN FAILED` — generation failed, carrying
  provider/model/reason.

Both appear in the backend log with the full context.

## Endpoints

| Endpoint | Purpose |
|---|---|
| `POST /api/v1/chat/generate-title` | Generate a title from a single assistant message (chat-page rename / auto-title) |
| `POST /api/v1/sessions/{id}/title` | Generate from the session's full conversation (Sessions-page smart rename) |
| `GET /api/v1/chat/title-service/status` | Current resolution (provider/model/reasoning-effort) + default-provider readiness |
| `GET /api/v1/chat/title/metrics` | Attempt/success/failure counts + average time |

## Where the model comes from (the config surfaces)

- The **Settings → General → Title Generation** section holds the
  user-facing preference: auto-title on/off, model source
  (agent/backend-default/custom), and the custom model string.
- The **providers** table is the source of truth for the provider
  rows (the default row = `is_default`). Keys live in `.env`
  (env_key_store).
